# 로컬 일일 실행

`ops/run-daily.ps1`은 수집 → 새 예측 또는 재사용 → 이전 예측의 실제값 확인 → 평가 → 개인 보고서 갱신을 실행합니다. 기존 `run-local.ps1`의 과거 시점 dry-run과 별개입니다. 공개 Git 원장, 공개 홈페이지, 외부 타임스탬프, 알림 서비스에는 쓰지 않습니다. 유료 클라우드나 새 서비스가 필요하지 않습니다.

저장소 루트에서 이미 준비된 런타임 설정을 사용합니다. 이 예제의 `work/model-smoke/runtime.env`와 모델 캐시는 저장소 밖의 개인 파일입니다. 다른 컴퓨터에서는 경로를 해당 환경에 맞춰야 합니다.

```powershell
# 로컬 Python 3.11.17 모델 환경, 정확한 모델 revision 및 기존 가중치 검사.
# 데이터 수집·모델 추론·작업 등록은 하지 않습니다.
.\ops\run-daily.ps1 -RuntimeEnvFile ..\..\work\model-smoke\runtime.env -CheckOnly

# 실제 KST 날짜로 오늘 실행. 새 예측이 허용된 시간이면 실제 7개 모델 실행.
.\ops\run-daily.ps1 -RuntimeEnvFile ..\..\work\model-smoke\runtime.env

# 모델 실행 없이 수집, 기존 예측의 결과 평가, 보고서만 갱신.
.\ops\run-daily.ps1 -RuntimeEnvFile ..\..\work\model-smoke\runtime.env -EvaluateOnly
```

`-StateDir <개인 경로>`로 저장 위치를 바꿀 수 있습니다. 기본값은 이 작업 폴더의 `work/tsfm-local-daily`이며 저장소 안의 경로는 거부합니다. `.env`를 셸 코드로 실행하지 않고 허용된 런타임 경로·설정만 읽습니다. 게시·알림·모델 서비스 토큰은 실행 환경에서 제거합니다. 모델 파일은 오프라인 캐시에서 읽으며 새 패키지나 가중치를 설치하지 않습니다.

## 날짜와 마감

- 실행일은 실제 실행 시각의 `Asia/Seoul` 날짜입니다. 과거 날짜를 넣거나 누락된 날을 채워 넣는 옵션이 없습니다.
- 새 예측은 **08:10 이상, 08:48 미만 KST**에만 시작합니다. 수집·런타임 검사 이후에도 시간을 다시 확인합니다. 기존 파이프라인의 2분 여유와 08:50 마감 규칙을 그대로 사용합니다.
- 예측의 시작·생성 완료 시각, 입력 문맥 해시, 원자료 해시와 조회 시각을 보관합니다. 완료가 08:50 또는 대상 관측 시각에 도달하면 해당 예측을 `void`로 기록하고 평가하지 않습니다.
- 08:48 이후나 08:10 이전 실행은 수집·이전 예측 평가·내보내기를 계속하고 새 추론만 사유와 함께 건너뜁니다. 늦은 실행을 08:10에 실행한 것으로 바꾸지 않습니다.
- 목표는 각 지표의 **다음 세션 관측값**입니다. 휴장일, 시차 때문에 일괄적으로 “내일”이라고 표시하지 않습니다.
- 이 시간 기록은 개인 컴퓨터의 시계와 파일에 의존합니다. 외부에서 검증된 공개 확정 예측 기록이 아니며, 미래에 공개 운영을 켜더라도 이 개인 기록을 소급 편입하지 않습니다.

## 재시작과 평가

동일 저장 경로에는 프로세스 잠금이 하나만 허용됩니다. 이미 실행 중이면 `already_running`으로 종료합니다. 성공적으로 저장된 날짜별 예측은 동일 날짜의 재실행에서 원래 바이트를 재사용합니다. 이미 완료된 모델 일부만 다시 실행해 선택하지 않습니다. 추론 도중 프로세스가 종료되어 예측 파일이 없으면 같은 날 실행창 내에서 최대 두 번까지 추론 시도를 허용합니다. 기존 입력 캐시가 달라지면 기존 파이프라인의 `context_cache_conflict` 규칙으로 중단합니다.

원자료 수집은 실패한 소스만 기본 2회 시도합니다(`-Retries 1..3`). 개별 HTTP 소스에도 기존 제한 시간과 유한 재시도가 있습니다. 완료된 모델 실패를 자동 재추론하지 않습니다. 내보내기만 최대 지정 횟수 재시도합니다. 오류 로그에는 예외 유형을 기록하고 토큰이 포함될 수 있는 예외 메시지/트레이스백은 남기지 않습니다.

대상 시각이 지난 예측에만, 조회·발표 시각이 확인된 실제값을 연결합니다. 원래 입력의 마지막 값으로 수익률 또는 bp 변화량을 계산합니다. 13개 분위수의 기존 점수 계산을 사용하며 지표·모델별 표본 수, MAE, RMSE, CRPS, 80% 구간 포함률을 제공합니다. 단위가 다른 지표를 섞어 통합 순위를 만들지 않습니다. 실제값 대기와 프로토콜의 5일 유예 후 `actual_unavailable`을 구분합니다.

실제값과 점수는 실행별 배치로 추가합니다. 오전에 빈 배치를 썼더라도 같은 날 저녁 재실행에서 추가 평가할 수 있습니다. 이미 평가한 `(예측일, 지표, 모델)`은 중복 계산하지 않습니다. 원자료가 나중에 수정되면 `revision_observed_not_applied` 이벤트와 `partial` 상태로 알리고 기존 실제값/점수를 보존합니다. 변경된 소스·단위·관측시각 정의로 과거 예측을 조용히 재평가하지 않습니다.

## 파일과 상태

개인 저장 위치의 구조는 다음과 같습니다.

```text
latest-run.json                 # 마지막 실행의 단계별 결과
attempts/<timestamp-id>.json     # 실행별 불변 로그, 실패/건너뜀 사유
days/YYYY-MM-DD/forecast.json    # 개인 예측 + 생성 완료 시각 + 해시 + 고정 설정
days/YYYY-MM-DD/inference-attempt-*.json
cache/contexts/YYYY-MM-DD/*.json # 원래 입력·마지막 값; 삭제하면 무결성 검사 실패
cache/raw/                      # 원자료 재현 캐시(실제 소스별 구조 사용)
batches/<timestamp-id>.json      # 추가 실제값·점수·수정 관측 이벤트
source-audit/                   # 선택적 소스 점검 보고서
reports/index.html              # 파일로 열 수 있는 개인 보고서
reports/latest.json             # 최근 7일 관측값·예측·점수·실행 상태
```

단계 상태는 `ok`, `partial`, `failed`, `skipped`이며 건너뜀 사유가 별도로 있습니다. 전체 종료 코드는 정상/의도된 건너뜀은 0, 실패 또는 일부 실패는 1입니다. 마감 밖 실행이 0이라는 사실만으로 예측 생성 성공을 뜻하지 않습니다. `forecast_counts`와 `stages.forecast.reason`을 확인해야 합니다. `days`, `batches`, 원래 `cache/contexts`를 함께 백업하세요. 손상된 예측·문맥 해시는 실패로 처리합니다. 임시 `.tmp`는 완성된 기록으로 읽지 않습니다.

보고서는 `level` 표시가 허용된 지표만 원래 단위의 값을 보여 줍니다. `return_only` 지표는 변환된 수익률 또는 bp 값만 내보냅니다. “오늘” 값은 최신 이용 가능한 **일별** 관측이며 실시간 장중 값이 아닙니다. 최근 7일은 그 관측 날짜까지의 7개 달력 날짜라 휴장일에는 점이 없을 수 있습니다. 지난 예측은 `expired`로 유지합니다. TiRex 모델은 [고정된 라이선스와 출처](../site/public/licenses/tirex.txt)의 조건을 따릅니다.

## 소스 재점검

일일 실행은 `tsfm_live.source_probe`가 있으면 추론 이후 소스 목록·미해결 조건을 점검합니다. 기본 점검은 네트워크 요청을 하지 않습니다. 실제 수집 단계는 활성화된 소스에서 데이터를 요청합니다. 별도의 제한된 공식 엔드포인트 재점검까지 원하는 경우에만 `-SourceProbeNetwork`를 추가합니다.

```powershell
.\ops\run-daily.ps1 -RuntimeEnvFile ..\..\work\model-smoke\runtime.env -EvaluateOnly -SourceProbeNetwork
```

점검은 소스나 후보 지표를 자동 활성화하지 않습니다. 소스별 상태는 `not_checked`, `blocked_not_requested`, `fresh`, `lagging`, `source_error`, `no_observations`입니다. 자세한 결과는 `source-audit/latest.json` 및 [소스 재점검](data-sources-recheck.md)에 있습니다.

## 작업 스케줄러용 코드

작업은 자동 등록하지 않았습니다. 다음 스크립트의 기본 동작은 정의 미리보기입니다. Windows 시간대가 `Korea Standard Time`인지 검사하고 시스템 시간대를 변경하지 않습니다.

```powershell
.\ops\configure-daily-task.ps1 -RuntimeEnvFile ..\..\work\model-smoke\runtime.env
# 검토 후 사용자가 실행할 등록/해제 명령:
.\ops\configure-daily-task.ps1 -RuntimeEnvFile ..\..\work\model-smoke\runtime.env -Action Install
.\ops\configure-daily-task.ps1 -Action Uninstall
```

등록하면 매일 06:10 KST에 이전 결과 수집·평가, 08:10 KST에 새 예측까지 실행합니다. 06:10은 실행창 이전이므로 모델을 실행하지 않습니다. 현재 사용자 로그인이 필요하며 암호를 저장하지 않습니다. 중복 인스턴스는 무시하고 실행시간을 1시간으로 제한합니다. 절전·전원 종료·로그아웃 상태에서 적시 실행을 보장하지 않습니다. 지연 실행은 실제 실행시각 규칙에 따라 새 예측을 건너뜁니다. 이미 같은 이름의 작업이 있으면 덮어쓰지 않습니다.

## 공개 홈페이지 운영과의 차이

이 실행기는 공개 사이트를 갱신하지 않습니다. 공개 운영은 기존 `tsfm-live run`/`GitPublisher` 경로에서 별도로 구성해야 합니다. 인증된 `git`/`gh`의 해당 저장소 게시 권한, 정확한 저장소·운영자 연락처·`TSFM_PUBLIC_ORIGIN`, 필수 CI 검사 `pipeline`/`site`, 런타임·데이터 준비 상태를 확인하고 명시적으로 `TSFM_LIVE_ENABLED=1`을 설정해야 합니다. 필요할 경우 외부 타임스탬프 CLI와 알림 수신 대상도 따로 구성합니다. 당일 실행창·공개 커밋 확정·08:50 마감 검증은 생략할 수 없습니다. 로컬 일일 파일이나 역사적 dry-run을 공개 확정 기록으로 옮기는 기능은 제공하지 않습니다.

현재 컴퓨터에서 7개 TSFM의 실제 가중치 실행과 3개 지표의 1일 역사적 통합 실행은 검증되어 있습니다. 이 새로운 실행기의 무중단 일일 운용, 작업 스케줄러 등록, 누적 예측 정확도, 공개 적시 게시 실적은 아직 별도 운영 증거가 필요합니다.

## 이번 통합 검증

2026-10-11 전체 Python 검증은 258개 중 256개 통과, 이 Windows 환경의 POSIX 셸·심볼릭 링크 권한 관련 기존 검사 2개 건너뜀으로 완료했다. Ruff, 원장 검증, 두 PowerShell 실행기의 구문 검사와 작업 정의 미리보기도 통과했다. 기존 기본 임시 폴더에 접근 제한이 있어 전체 검증에는 이 작업의 별도 임시 디렉터리를 사용했다.

실제 `-EvaluateOnly -SourceProbeNetwork` 실행은 2026-10-11 06:14:05–06:14:30 UTC에 정상 완료했다. 활성 3개 소스 수집과 후보 8개 최신성 점검을 수행하고 개인 JSON/HTML 보고서를 저장했다. 새 모델 추론은 요청한 평가 전용 모드로 건너뛰었으며, 기존 개인 예측이 없어 실제값 연결·점수는 0개다. 실제 예측 정확도나 여러 날 연속 운용을 검증했다는 뜻은 아니다. 작업 스케줄러에는 등록하지 않았다.
