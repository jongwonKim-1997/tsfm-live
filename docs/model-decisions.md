# Model implementation decisions

These entries are inputs to the main ADR log. Reviewed 2026-10-08.

1. **Uniform information.** Every TSFM receives only the same finite one-dimensional transformed context. Chronos cross-learning is false. No covariates, externally engineered scaling, clipping, or fine-tuning are introduced. Package-internal normalization remains enabled where documented.
2. **EWMA indexing.** The first 20 context observations initialize an unbiased sample variance. Observations 21 through the final observed value update `v = .94*v + .06*y*y`. The resulting sigma is the next-session scale. The regime threshold uses the last 250 available values of this observed-only sigma path, including its current endpoint; comparison is `>=` as specified. The path starts only when the 20-value initialization exists.
3. **Sparse grids.** Native grids are sorted before interpolating. Tails use the slope of the nearest two native levels, rather than the flat clamping used by some vendor convenience APIs. Outputs explicitly say `interpolated` unless every requested level exists natively. Sorting enforces monotonicity. This tail approximation is not a calibrated 95% interval guarantee and remains visible in records.
4. **Mean versus median.** Chronos, Bolt, and TiRex convenience fields labelled mean actually contain medians; benchmark `mean` is null for them. TimesFM's first tuple member is also median, but its full head channel 0 provides the mean. Sample models use the empirical mean of the same 1000 draws.
5. **Deterministic failures.** SHA-256-derived per-date/indicator/model seeds avoid Python's randomized hash. Torch deterministic algorithms are enabled without `warn_only`; unsupported deterministic operations fail audibly rather than rerunning nondeterministically. Runtime/dependency pins are recorded separately from cross-hardware numerical reproducibility.
6. **Incompatible dependencies.** CPU Python 3.11 model profiles are isolated. Moirai requires Torch <2.5, Toto pins Torch 2.7 and Transformers 4.52.1, and Sundial requires Transformers 4.40.1. They cannot be honestly represented as one working optional dependency group. `models.worker` provides a one-request JSON subprocess boundary; the parent enforces the 120-second deadline and chooses the profile interpreter. Runtime weights are offline-only by default and are warmed separately using the pinned revision.
7. **TiRex.** Current official source includes a pure Torch CPU backend. Use it initially, avoiding custom CUDA compilation. Actual Windows CPU execution and offline-worker checks now pass; the entrant is enabled with the required attribution in catalog metadata and site copy. Other-host support and full-run timeout performance still require measurement.
8. **TabPFN.** Optional entrant remains disabled and has no runnable adapter until authenticated local licence acceptance, cached exact weights, telemetry behavior review, and a local smoke test are completed. No cloud inference/API fallback or account creation is performed. Calendar features would be disabled if implemented so the protocol's context-only contract remains true.
9. **Remote code.** Sundial's four source files were reviewed at one exact commit. Both model revision and `code_revision` are pinned and the adapter checks a matching audit ID. Unreviewed revisions fail closed. This is source inspection, not a claim that remote code is intrinsically safe.
10. **No artificial coverage.** Seven real package adapters are implemented; eight model catalog entries are present. Implemented, installed, weight-validated, daily-operational, and launch-ready are separate states. Tests of baseline mathematics and protocol plumbing do not count as live TSFM forecasts. No missing model returns a fabricated baseline.
11. **Runtime evidence.** All seven implemented TSFMs passed the same 512-observation, 13-quantile CPU smoke and exact replay, followed by an offline fresh-process worker with identical outputs. Sample models use 1000 generated draws. This enabled their catalog entries but did not change any `launch_ready` flag or create a live ledger record. Evidence and limitations are in `docs/model-smoke.json` and `docs/model-smoke.md`.
12. **Sampling seed boundary.** Real Toto validation showed that constructing the model consumes RNG draws before inference. Sample adapters therefore reseed after weight loading, so identical seeds produce identical samples for both a cold and a reused model. The test was rerun and passed; no mismatching output was recorded as runtime-verified.
